# §3.1 — Session de refactor avec `/compact`

Trace pédagogique d'une session Claude Code menée sous **pression du contexte**.
Objectif : refactorer `src/components/Board.tsx` en séparant ses responsabilités,
en se servant de `/compact` au bon moment pour ne pas laisser le contexte saturer.

## Module refactoré

`src/components/Board.tsx`.

## Avant

- 137 lignes dans un seul fichier.
- Trois responsabilités mêlées :
  1. **Rendu canvas** — `drawGrid` (34 lignes) + 5 constantes de cellule.
  2. **Gestion d'état** — `useState<SimulatorState>`, `useEffect` boucle d'animation,
     six `useCallback` (handlers Play / Pause / Step / Reset / Speed / Pattern).
  3. **Composition JSX** — assemblage `PatternSelector` + `GenerationCounter` +
     `SimulatorControls` + `<canvas>`.

Symptôme typique pour Claude : pour ajouter un test sur `drawGrid` ou modifier
la boucle d'animation, il devait lire tout le fichier (rendering + state +
composition) — beaucoup de bruit pour une chirurgie locale.

## Après

| Fichier | Rôle | Lignes |
|---------|------|-------:|
| `src/components/Board.draw.ts` | Drawing canvas pur (aucune dépendance React) | 64 |
| `src/components/Board.draw.test.ts` | Test sibling sur `drawGrid` (stub `CanvasRenderingContext2D`) | 78 |
| `src/components/use-simulator.ts` | Custom hook : state + boucle + handlers | 84 |
| `src/components/Board.tsx` | Composition pure : hook + JSX | 60 |

`Board.tsx` est passé de **137 lignes / 3 responsabilités** à **60 lignes /
1 responsabilité (composition)**. Les deux modules extraits sont testables
isolément (`Board.draw.ts` via Vitest, `use-simulator.ts` via composant en
e2e plus tard).

## Conduite de session — où `/compact` a servi

Découpage en deux phases volontairement séquentielles :

1. **Phase A — extraction du drawing**
   - Lecture ciblée : seulement `Board.tsx` et la section "Architecture" de
     `CLAUDE.md`. Pas de tour de l'arborescence.
   - Création de `Board.draw.ts` (fonctions internes `paintBackground`,
     `paintAliveCells`, `paintGridLines` extraites de `drawGrid` pour
     respecter la limite ≤ 50 lignes du `CLAUDE.md`).
   - Création du test sibling avec un stub de `CanvasRenderingContext2D`.
   - Import de `drawGrid` dans `Board.tsx`, suppression des constantes locales.
   - `npm test` vert (les 11 tests + 4 nouveaux).

2. **`/compact` ici.** À ce stade le contexte contenait :
   - Le contenu de l'ancien `Board.tsx` (137 lignes).
   - Tout le détail de la création des trois sous-fonctions de paint.
   - L'itération sur le stub de canvas.
   - Les traces `npm test` de la phase A.

   Ce qu'on garde après compact : **le contrat** des fonctions à extraire en
   phase B (`useSimulator`, signature `{ state, pattern, handlers }`), la
   liste des handlers à conserver, l'objectif **≤ 70 lignes** pour
   `Board.tsx`. Tout le reste (implémentation détaillée de phase A) est
   résumé en une note. Gain de contexte estimé : ~75-85 %.

3. **Phase B — extraction du hook**
   - Création de `use-simulator.ts` (custom hook, `'use client'`) regroupant
     `useState`, `useEffect` boucle d'animation, et les six `useCallback`.
   - Réduction de `Board.tsx` à la composition pure : appel du hook + JSX.
   - `npm test` toujours vert. Comportement runtime identique (canvas
     s'anime, slider règle la vitesse, PatternSelector reset le simulator).

## Pourquoi entre A et B, pas après ?

- **Frontière naturelle** : la phase A est self-contained et déjà commitable.
  C'est le bon moment pour résumer — la phase B repart d'un état propre,
  validé par les tests.
- **Garde-fou** : si la phase B partait mal (mauvaise signature du hook,
  oubli d'un handler), la phase A serait déjà sécurisée. `/compact` agit
  comme un "save point" cognitif.

## Mesure synthétique

- **Avant** : 1 fichier, 137 lignes, 3 responsabilités, 0 test direct.
- **Après** : 4 fichiers, 60 + 64 + 78 + 84 = 286 lignes (plus de lignes au
  total parce que les tests ajoutent ~80 lignes), **mais** 1 responsabilité
  par fichier, et un point de test direct sur le drawing.
- **Pour Claude** : prochaine modif sur la boucle d'animation → ouverture
  ciblée de `use-simulator.ts` (~84 lignes), pas du fichier de composition.
- **Tests** : 11 → 15 (4 cas ajoutés sur `drawGrid`).

## À retenir

- `/compact` n'est pas un nettoyage cosmétique : c'est un outil de **gestion
  active** du contexte. On l'utilise *avant* la saturation, sur une frontière
  logique (fin d'une phase, validation par les tests).
- Le découpage du travail en phases courtes + validation par tests rend
  `/compact` sûr : ce qui survit au résumé est l'intention, pas le détail.
- L'effet cumulatif sur une session de 2-3 h : 2-3 `/compact` bien placés =
  on tient toute la séance sans `/clear` ni perte de fil.
