Trois étapes : d'abord créer **deux skills** versionnés dans le repo (`.claude/skills/`), ensuite utiliser le premier skill pour scaffolder un mini-composant, et enfin utiliser le second pour ajouter un test au moteur Conway. Le second skill **référence** le premier — c'est la démo de *composable skills*.

Un skill, c'est un dossier qui contient un `SKILL.md` (frontmatter `name` + `description` + corps). Claude le déclenche automatiquement quand le contexte matche la description — pas besoin de l'invoquer. Scope projet = dans `.claude/skills/`, versionné (miroir inverse du plugin §2.5 installé au scope utilisateur).

---

## Étape 1 — Créer les deux skills

Crée la structure suivante à la racine du repo :

```
.claude/skills/
├── next-component/
│   └── SKILL.md
└── vitest-test/
    └── SKILL.md
```

### `.claude/skills/next-component/SKILL.md`

Le skill `next-component` doit produire un composant React Next 16 idiomatique :

- Frontmatter : `name: next-component` + une `description` qui dit clairement *quand* Claude doit l'invoquer (ex. « Génère un composant React Next 16 dans `src/components/` »).
- Règles que tu veux voir appliquées dans le corps : `'use client'` seulement si le composant gère un état ou des handlers, props typées via `interface`, pas de `React.FC`, classes Tailwind sobres (noir/blanc — cf. style §2.5).

### `.claude/skills/vitest-test/SKILL.md`

Le skill `vitest-test` doit produire un test Vitest pour une fonction ou un composant :

- Frontmatter : `name: vitest-test` + une `description` qui couvre les deux cas (fonction pure ET composant React).
- Règles dans le corps : structure AAA / given-when-then, `describe` + `it`, helpers nommés.
- **Composition** : précise explicitement dans le corps que **pour un composant React, le skill `next-component` est appliqué d'abord** — pose un lien `@.claude/skills/next-component/SKILL.md` ou cite-le nominativement. C'est cette mention qui prouve la composition.

## Étape 2 — Utiliser les skills (deux prompts à Claude)

### 2.a — Mini-feature avec `next-component`

Une fois les deux skills posés, copie-colle ce prompt :

> Crée un nouveau composant `src/components/GenerationCounter.tsx` qui affiche « Génération N°{count} » (props `{ count: number }`, Tailwind sobre, monochrome). Composant purement présentationnel, pas d'état interne.
>
> Ensuite, dans `src/components/Board.tsx` (déjà client component depuis §2.6), ajoute un `useState<number>` `generation` initialisé à 0, incrémenté à chaque clic sur le bouton « Next » (en plus de l'appel à `step`). Monte `<GenerationCounter count={generation} />` à côté du bouton.
>
> Le skill `next-component` doit être appliqué automatiquement pour le scaffolding du composant.

### 2.b — Test core/ avec `vitest-test`

Puis :

> Ajoute dans `src/core/step.test.ts` un test pour l'oscillateur **toad** (4 cellules en forme de T horizontal qui devient T vertical, période 2 — cf. doc Conway). Ne touche pas à `step.ts` : la règle B3/S23 le couvre déjà.
>
> Le skill `vitest-test` doit être appliqué automatiquement pour la rédaction du test.
