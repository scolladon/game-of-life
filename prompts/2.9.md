Trois étapes : d'abord poser **trois slash commands** versionnées dans `.claude/commands/`, ensuite livrer l'UI finale du Game of Life (Canvas HTML5 + boucle d'animation Play/Pause/Step/Speed/Reset), enfin valider. Comme les agents §2.8, les slash commands sont au scope projet — partagées en équipe via le repo (miroir inverse du plugin §2.5).

Une slash command, c'est un fichier `.claude/commands/<nom>.md` avec un frontmatter optionnel (`description`, `argument-hint`, `allowed-tools`) et un corps qui sert de prompt template. Trois mécaniques de templating : `$ARGUMENTS` (tout ce qui suit `/nom`), `@chemin` (inline un fichier), `!cmd` (exécute un shell et inline le résultat).

---

## Étape 1 — Créer les trois slash commands

Crée la structure suivante :

```
.claude/commands/
├── review.md
├── explain.md
└── refactor.md
```

### `.claude/commands/review.md`

- Frontmatter : `description` claire (ex. « Relit le diff courant et classe les findings par sévérité (CRITICAL/HIGH/MEDIUM/LOW). »), `argument-hint: "[chemin optionnel]"`, `allowed-tools: Read, Grep, Glob, Bash` (lecture seule).
- Corps : un prompt qui demande à Claude de relire le diff (`!git diff HEAD`) ou la cible passée en `$ARGUMENTS`. Format de rapport = liste classée par sévérité. Pas de réécriture, uniquement observations.

### `.claude/commands/explain.md`

- Frontmatter : `description` qui dit que la commande explique un fichier / symbole / concept (pédagogique). `argument-hint: "<chemin|symbole|concept>"`. `allowed-tools: Read, Grep, Glob` (lecture seule, pas de bash).
- Corps : prompt qui prend `$ARGUMENTS`, ouvre le fichier ciblé (`Read`/`Grep`), et explique en français sobre — entrée, sortie, invariants, pièges. Adapte la profondeur au niveau du lecteur.

### `.claude/commands/refactor.md`

- Frontmatter : `description` axée refactor sûr d'un fichier ou symbole, respectant les frontières `CLAUDE.md` (séparation `core/` ↔ `components/`, immutabilité, pureté). `argument-hint: "<chemin>"`. `allowed-tools: Read, Edit, Grep, Glob, Bash` (a le droit d'éditer, mais reste prudent).
- Corps : prompt qui prend `$ARGUMENTS` (chemin obligatoire), lit `@CLAUDE.md` pour le contexte projet, identifie 2-3 refactors ciblés (extraction de fonction, immuabilité, frontières de couche), les applique, lance `npm test` via `!npm test`. Refuse si pas de test associé.

## Étape 2 — Livrer la feature (un seul prompt à Claude)

Une fois les trois commandes posées, copie-colle ce prompt :

> Livre l'UI finale du Game of Life en trois étapes.
>
> 1. Crée `src/core/simulator.ts` — moteur de boucle de simulation **pur** (zéro DOM, zéro React) :
>    - Type `SimulatorState = { grid: Grid; generation: number; speedMs: number; isRunning: boolean }`.
>    - `createSimulator(initialGrid: Grid, speedMs: number): SimulatorState` — facteur (état initial, immuable).
>    - `tick(state: SimulatorState): SimulatorState` — avance d'une génération (utilise `step` du §2.3).
>    - `setSpeed(state, speedMs): SimulatorState` — change la vitesse, retourne un nouvel état.
>    - `setRunning(state, isRunning): SimulatorState` — toggle play/pause.
>    - `reset(state, initialGrid): SimulatorState` — remet `generation` à 0 et `isRunning` à false.
>    - Tous les retours sont des **nouveaux objets** (immutabilité, cf. `CLAUDE.md`).
>    - Test co-localisé `src/core/simulator.test.ts` (AAA, `sut`) qui couvre les 5 fonctions. Déclenche `@test-writer` si disponible.
>
> 2. Crée `src/components/SimulatorControls.tsx` (client component, `'use client'`) :
>    - Props : `{ isRunning: boolean; speedMs: number; onPlay: () => void; onPause: () => void; onStep: () => void; onReset: () => void; onSpeedChange: (ms: number) => void }`.
>    - Rend 4 boutons (Play / Pause / Step / Reset) + un `<input type="range">` pour la vitesse (50 -> 1000 ms, step 50).
>    - Tailwind sobre, monochrome — comme `PatternSelector`.
>    - Pas de logique métier — uniquement présentation + relais des callbacks.
>
> 3. Modifie `src/components/Board.tsx` :
>    - Remplace l'affichage grille-DOM (la matrice de `<div role="gridcell">`) par un `<canvas>` HTML5 rendu via `useRef<HTMLCanvasElement>` + `useEffect` qui redessine à chaque changement de `grid`. Taille de cellule fixe (ex. 24px), couleurs noir/blanc + bordures gris clair.
>    - Utilise `createSimulator` / `tick` / `setSpeed` / `setRunning` / `reset` au lieu du `useState<Grid>` brut.
>    - Boucle d'animation : `useEffect` qui démarre un `setInterval(tick, speedMs)` quand `isRunning` est `true`, et l'arrête sinon. Cleanup propre.
>    - Monte `<SimulatorControls ... />` à côté du `PatternSelector` et du `GenerationCounter`.
>    - Le changement de pattern (`PatternSelector`) doit appeler `reset(...)` du simulator (pause + génération 0 + nouvelle grille).
>
> Une fois le code écrit, exécute `/review` puis `/refactor src/components/Board.tsx` pour la passe finale.
