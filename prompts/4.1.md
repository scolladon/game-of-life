# Bouée §4.1 — Engineering harness (`/quality-gate` + sous-agents qualité + CI)

> À utiliser **uniquement** si tu es bloqué après 15 minutes. Essaie d'abord de formuler ton propre prompt.

## Contexte

§4.1 assemble l'**engineering harness** du projet : trois sous-agents qualité **objectifs** (types, lint, coverage), une slash command `/quality-gate` qui les orchestre en parallèle, et un workflow GitHub Actions qui rejoue les mêmes commandes côté serveur.

Différence avec §2.8 (agents) : les agents §2.8 (`code-reviewer`, `architect-reviewer`, `test-writer`) rendent un **jugement** (sévérités, recommandations). Les agents §4.1 rendent un **verdict binaire** (PASS / FAIL) basé sur un outil objectif (`tsc`, `biome`, `vitest`).

## Prompt copier-collable

```
Assemble l'engineering harness §4.1. Trois étapes : trois sous-agents qualité
versionnés (.claude/agents/quality-*.md), une slash command /quality-gate
versionnée (.claude/commands/quality-gate.md) qui les orchestre en parallèle,
un workflow GitHub Actions (.github/workflows/ci.yml) qui rejoue les mêmes
commandes en CI.

=== Étape 1 — Trois sous-agents qualité (.claude/agents/) ===

Pour chaque agent : frontmatter `name` (kebab-case = nom de fichier) +
`description` >= 30 caractères qui décrit clairement quand l'invoquer +
`tools: Read, Grep, Glob, Bash`.

1. `.claude/agents/quality-types.md`
   - description : "Vérifie le typage TypeScript strict du projet via
     `tsc --noEmit`. Verdict objectif. À utiliser avant tout commit non-trivial
     et systématiquement par `/quality-gate`."
   - Corps : exécute `npx tsc --noEmit` (timeout 120s), parse stdout/stderr,
     rapport `[FAIL] <fichier>:<ligne> — <message>` ou `[PASS] tsc clean`.
     Pas de modification de fichier.

2. `.claude/agents/quality-lint.md`
   - description : "Vérifie le respect du lint Biome (formatage + erreurs)
     via `biome check`. Verdict objectif. À utiliser avant tout commit
     non-trivial et systématiquement par `/quality-gate`."
   - Corps : exécute `npx biome check`, rapport `[FAIL] <fichier>:<ligne> —
     <règle>` ou `[PASS] biome clean`.

3. `.claude/agents/quality-coverage.md`
   - description : "Vérifie que les tests Vitest passent et que la couverture
     du dossier `src/core/` est à 100 %, ≥ 80 % ailleurs (cf. CLAUDE.md).
     À utiliser avant tout commit non-trivial et systématiquement par
     `/quality-gate`."
   - Corps : exécute `npx vitest run --coverage`, lit le rapport, FAIL si un
     test rouge ou seuil core/ < 100 %, sinon PASS.

=== Étape 2 — Slash command /quality-gate (.claude/commands/quality-gate.md) ===

Frontmatter :
  description: "Exécute l'engineering harness : `quality-types`,
                `quality-lint`, `quality-coverage` en parallèle, agrège leurs
                rapports, rend un verdict global PASS / FAIL."
  allowed-tools: Read, Grep, Glob, Bash

Corps :
  - Dispatche les 3 sous-agents en parallèle (« Use the `quality-types`,
    `quality-lint`, and `quality-coverage` agents in parallel »).
  - Concatène les rapports, classe par sévérité.
  - Verdict final : PASS si les 3 PASS, FAIL sinon (lister les blockers).
  - Ne modifie aucun fichier.

=== Étape 3 — Workflow GitHub Actions (.github/workflows/ci.yml) ===

Trigger :
  push:
    branches: [main, solution]
  pull_request:
    branches: [main]

4 jobs (tous en `ubuntu-latest`, Node 22, cache npm) :
  - lint : `npm ci && npm run lint`
  - test : `npm ci && npm run test:run`
  - check : `npm ci && npm run check`
  - typecheck : `npm ci && npx tsc --noEmit`

Pas de secrets, pas de service externe payant. Le repo `game-of-life` sera
poussé public à la fin de la formation — la config doit tourner telle quelle
sur les runners gratuits GitHub Actions.

=== Étape 4 — Vérification ===

npm run check:4.1     # ✅
npm run check         # 14/15 ✅ (1.4 → 4.1)
npx tsc --noEmit      # clean
npm test -- --run     # vert
```

## Pièges

- **Ne pas dupliquer §2.8** — les agents `code-reviewer`, `architect-reviewer`,
  `test-writer` restent en place. §4.1 ajoute 3 agents **différents** (verdict
  objectif vs jugement).
- **CI sur `solution`** — il faut explicitement la mentionner dans `branches:`
  côté `push`, sinon le workflow ne tourne que sur main.
- **Coverage 100 % core/** — c'est ce que dit `CLAUDE.md` et le DESIGN. Vérifier
  que `vitest.config.ts` cible bien `src/core/` (sinon, le sous-agent
  `quality-coverage` mesure du vide).
- **Pas d'emoji** dans les agents et la slash command — convention du repo
  formation (cf. §2.8, §2.9).
