Deux étapes : d'abord brancher un serveur MCP public (Context7) au repo, ensuite demander à Claude de t'ajouter un bouton « Next » en s'appuyant sur la doc à jour récupérée via ce MCP.

## Étape 1 — Déclarer Context7 dans `.mcp.json` (scope projet)

Contrairement à un plugin (§2.5 — install au scope utilisateur), un serveur MCP peut être **versionné dans le repo** via un fichier `.mcp.json` à la racine. Tout le monde qui clone bénéficie alors du MCP, sous réserve d'avoir `npx` dispo.

Crée à la racine de `game-of-life/` un fichier `.mcp.json` :

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp@latest"]
    }
  }
}
```

Puis **redémarre la session Claude Code** (sors et relance `claude` dans le dossier) — un nouveau MCP n'est chargé qu'au démarrage.

Vérification rapide depuis Claude :

```text
/mcp
```

`context7` doit apparaître dans la liste, statut connecté. Si la commande t'invite à approuver un nouveau serveur MCP non-vérifié, accepte.

> Free tier sans clé : suffisant pour les quelques requêtes de cette démo. Si tu disposes d'une clé Context7, tu peux ajouter `"env": { "CONTEXT7_API_KEY": "..." }` à l'entrée du serveur — non requis ici.

## Étape 2 — Bouton « Next » (un seul prompt à Claude)

Objectif : la page d'accueil doit afficher le `<Board>` posé en §2.5, **et** un bouton qui fait avancer la grille d'une génération à chaque clic. C'est la première interaction utilisateur du jeu — elle exige de passer le composant en *client component* Next.js. Le piège : `AGENTS.md` te rappelle déjà que cette version de Next.js a changé. Profite de Context7 pour ne pas te tromper.

Copie-colle ce prompt :

> Avant d'écrire quoi que ce soit, utilise le MCP Context7 (`resolve-library-id` puis `query-docs`) pour récupérer la doc officielle de Next.js sur le split server / client components (`'use client'`) dans la version installée. Cite la portion pertinente en quelques lignes.
>
> Ensuite, modifie le projet :
>
> - **`src/components/Board.tsx`** : passe-le en client component (`'use client'` en première ligne). Il prend désormais une prop `initialGrid: Grid` (au lieu de `grid`), gère son état interne avec `useState<Grid>(initialGrid)`, et expose un `<button>` libellé « Next » placé au-dessus de la grille. Le clic appelle `step` (importé depuis `@/core/grid`, §2.3) pour produire la génération suivante. Conserve le rendu Tailwind sobre du §2.5.
> - **`src/app/page.tsx`** : reste un server component, importe le seed blinker 5×5 existant et le passe sous `initialGrid={seed}` à `<Board>`.
> - Ne touche pas au moteur `src/core/` — la logique de transition est déjà testée (§2.3).
>
> Pas de test UI à ce stade (cf. §2.5). On validera par check + œil.
