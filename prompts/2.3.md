## Prompt A — Enrichir `CLAUDE.md`

Lis `CLAUDE.md`, `AGENTS.md`, `package.json` et la structure de `src/`.

Étends `CLAUDE.md` en **préservant l'existant** (la ligne `@AGENTS.md` et la
section `## Modèles et niveaux d'effort` doivent rester intactes). Ajoute trois
sections, dans cet ordre, à la suite de l'existant :

### `## Stack`

Liste les briques principales avec leur version (à lire dans `package.json`) :
Next.js, React, TypeScript, Tailwind, Vitest, Biome, Playwright, tsx. Une ligne
par brique, format `- **Nom X.Y** — rôle court`.

### `## Architecture`

Décris l'organisation en 4 couches du dossier `src/` :

- `src/core/` — **logique pure du Game of Life** (grille, step, règles).
  **Règle dure** : zéro dépendance Next/React/DOM/fetch/localStorage. Fonctions
  pures uniquement, données immutables (retourner de nouvelles structures, ne
  jamais muter les arguments).
- `src/app/` — routes Next.js (App Router). Pages, layouts, API routes.
- `src/components/` — composants React de présentation. Pas de logique métier
  (qui vit dans `core/` ou dans des hooks).
- `src/lib/` — adapters et utilitaires partagés (parsers, helpers I/O).

Termine par une phrase qui explique **pourquoi** `core/` doit rester pur (testable
isolément, portable vers un Web Worker plus tard, indépendant du framework).

### `## Conventions`

- **Naming** : `kebab-case.ts` pour les fichiers, `PascalCase` pour les composants
  React, `camelCase` pour fonctions et variables, `UPPER_SNAKE_CASE` pour les
  constantes.
- **Taille** : fichiers ≤ 400 lignes (extraire au-delà). Fonctions ≤ 50 lignes.
- **Tests** : co-localisés (`grid.ts` → `grid.test.ts` à côté). E2E à part dans
  `tests/e2e/`.
- **Types** : pas de `any`. Préférer `unknown` + type guard. Types stricts en
  exports publics.
- **Immutabilité** : `readonly` partout où c'est applicable côté `core/`.
- **Commits** : conventionnels (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`,
  `chore:`).

Cible totale du fichier : **≤ 150 lignes**. Sois concis, pas encyclopédique.
Chaque règle doit avoir une utilité opérationnelle pour qui contribue au repo.

Quand c'est fait, montre-moi le diff de `CLAUDE.md` et confirme que la ligne
`@AGENTS.md` et la section `## Modèles…` sont toujours là.

## Prompt B — Sème le moteur `core/`

Crée la première brique du moteur Game of Life dans `src/core/`, en respectant
**à la lettre** les règles d'architecture que tu viens d'écrire dans `CLAUDE.md`
(zéro dépendance Next/React/DOM, fonctions pures, immutable).

### 1. `src/core/grid.ts`

- Exporte un type `Grid` : grille rectangulaire de booléens, immutable
  (`readonly (readonly boolean[])[]` ou équivalent).
- Exporte `createGrid(width: number, height: number): Grid` — toutes cellules
  mortes (`false`).
- Exporte `getCell(grid: Grid, x: number, y: number): boolean` — renvoie `false`
  pour les coordonnées hors-grille (bord-mort).
- Exporte `cloneGrid(grid: Grid): Grid` — copie profonde immutable.
- Aucune mutation. Aucune dépendance externe.

### 2. `src/core/step.ts`

- Exporte `step(grid: Grid): Grid` — calcule la génération N+1 selon les règles
  classiques de Conway (**B3/S23**) :
  - Une cellule morte avec exactement 3 voisines vivantes naît.
  - Une cellule vivante avec 2 ou 3 voisines vivantes survit.
  - Sinon, elle meurt.
- Bord-mort (les cellules hors-grille comptent comme mortes).
- Pure et immutable : renvoie une nouvelle `Grid`, ne mute jamais l'entrée.

### 3. Tests Vitest co-localisés

- `src/core/grid.test.ts` :
  - `createGrid` produit les bonnes dimensions, toutes cellules à `false`.
  - `getCell` renvoie `false` pour coordonnées hors-grille (x < 0, y < 0,
    x ≥ width, y ≥ height).
- `src/core/step.test.ts` (au moins 3 cas) :
  - **Blinker** (oscillateur de période 2) : `___`/`OOO`/`___` → `_O_`/`_O_`/`_O_`
    puis retour à l'état initial après 2 steps.
  - **Block** (still life 2×2) : reste identique après 1 step.
  - **Glider** : après 4 steps, le pattern s'est déplacé d'une case en diagonale.

### 4. Vérifier

```bash
npm test               # tous les tests verts
npm run check:2.3      # check vert
```

Si `npm test` ne trouve rien, ajoute `include: ['src/**/*.test.ts']` au
`vitest.config.ts` (sans toucher au reste).
