# Bouée §3.3 — Workflow IA (PRD → Design → Plan → Implement)

> À utiliser **uniquement** si tu es bloqué après 15 minutes. Essaie d'abord de formuler ton propre prompt et de suivre le workflow toi-même.

## Contexte

Tu vas appliquer le **workflow IA** (PRD → Design → Plan → Implement, chacun reviewed) à une feature à **4 sous-blocs** sur le Game of Life :

1. **Variante HighLife** (règle B36/S23 au lieu de Conway B3/S23) — extension propre du moteur via paramètre `rule`.
2. **Sélecteur de règles** dans l'UI — Conway ↔ HighLife.
3. **Persistance SQLite** — sauvegarder/charger l'état (pattern, génération, règle, grille).
4. **Drizzle ORM** — couche de persistance au-dessus de `better-sqlite3`.

Objectif pédagogique : **discipliner** la collaboration avec le LLM en respectant les 4 phases et leur review. On ne saute pas d'étape — sinon on enseigne autre chose.

## Points de vigilance

- **Backward-compat `step`** : `step(grid)` sans rule doit toujours faire du Conway. Le 2e argument est optionnel.
- **Immutabilité** : pas de cache mutable dans `rules.ts`. Chaque appel `getRule` retourne la même constante mais frozen / readonly.
- **better-sqlite3 + Next 16 / Turbopack** : ce module natif ne tourne **que côté Node**. La persistance s'expose via une **route API** (`src/app/api/state/route.ts`), pas un import direct dans un component client. Le composant client appelle `fetch('/api/state', ...)`.
- **DB locale** : `data/game-of-life.db` — créer le dossier si absent, gitignorer (`data/`, `*.db`, `*.db-journal`).
- **Schema first** : la table `game_states` doit être créée au premier accès (idempotent `CREATE TABLE IF NOT EXISTS` ou `db.run(sql)` au boot du repository). Évite les migrations dans ce sous-bloc.
- **Tests Drizzle** : utiliser `better-sqlite3` avec `':memory:'` pour les tests unitaires du repository (rapide, isolé, pas d'I/O).
- **Pas d'auto-save** : un bouton "Save state" explicite suffit pour la démo.
- **Workflow > feature** : le check valide le code, mais la vraie valeur pédagogique est dans les 4 documents `PRD.md`, `DESIGN.md`, `PLAN.md` et la trace des reviews.
