## Prompt A — Hook `PostToolUse` Biome

Ouvre `.claude/settings.json`. **Préserve la clé `permissions` existante telle quelle** (elle vient de §2.2 et ne doit pas bouger).

Ajoute, à côté de `permissions`, une clé `hooks` qui déclenche **Biome** après chaque édition de fichier. La forme attendue :

```jsonc
{
  "permissions": { /* inchangé */ },
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs -r npx biome check --write --no-errors-on-unmatched"
          }
        ]
      }
    ]
  }
}
```

Explications à garder en tête (pas à mettre dans le fichier) :

- Le hook reçoit le JSON du tool call sur **stdin**. `jq -r '.tool_input.file_path'` en extrait le chemin du fichier.
- `xargs -r` n'invoque pas Biome si stdin est vide (sécurité).
- `--no-errors-on-unmatched` évite que Biome remonte une erreur quand le fichier est hors scope (ex. `.md`, `.mjs`).
- `--write` reformate en place.

Vérifie le résultat : le JSON doit rester valide (`cat .claude/settings.json | jq .` ne doit pas planter), et la clé `permissions` doit être strictement identique à avant.

Montre-moi le diff. Ne passe pas au prompt B tant que ce n'est pas validé.

## Prompt B — Hook `PreToolUse` garde-fou `core/`

Crée le fichier `.claude/hooks/guard-core.mjs` (Node ESM, < 50 lignes) qui défend la règle dure de `CLAUDE.md` (`src/core/` doit rester pur **et testé**).

### 1. `.claude/hooks/guard-core.mjs`

Comportement exact :

- Lit le JSON du tool call sur `process.stdin` (jusqu'à EOF), parse.
- Extrait `tool_input.file_path`.
- **Cas autorisés** (sortie : exit 0, rien sur stdout) :
  - `file_path` ne matche pas `src/core/...\.tsx?$` (hors scope, ex. `src/app/page.tsx`).
  - `file_path` est un fichier de test : se termine par `.test.ts` ou `.test.tsx`.
  - `file_path` est un fichier sous `src/core/` **et** son sibling de test existe sur disque (`grid.ts` → vérifier `grid.test.ts` dans le même dossier).
- **Cas bloqué** : `file_path` matche `src/core/<nom>\.tsx?$`, n'est pas un test, et son sibling `<nom>.test.<ts|tsx>` n'existe pas. Sortie attendue sur stdout :

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "core/ exige un test co-localisé (cf. CLAUDE.md §Architecture). Crée src/core/<nom>.test.ts d'abord."
  }
}
```

Puis `process.exit(0)` (la décision est portée par le JSON, pas par l'exit code).

Contraintes :

- ESM (`import` autorisé, pas de `require`).
- Aucune dépendance externe : `node:fs`, `node:path` uniquement.
- Pure, courte, idempotente.
- Si le JSON stdin est vide ou invalide → exit 0 silencieux (ne pas bloquer pour des raisons techniques).

### 2. Référencer le hook dans `.claude/settings.json`

Ajoute, dans la clé `hooks` (à côté du `PostToolUse` du prompt A), une entrée `PreToolUse` :

```jsonc
"PreToolUse": [
  {
    "matcher": "Edit|Write|MultiEdit",
    "hooks": [
      {
        "type": "command",
        "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard-core.mjs\""
      }
    ]
  }
]
```

### 3. Vérifier manuellement (avant `check:2.4`)

Quatre cas à tester depuis la racine du repo :

```bash
# 1. Fichier core/ avec test sibling → exit 0 (silencieux)
echo '{"tool_name":"Edit","tool_input":{"file_path":"src/core/grid.ts"}}' \
  | node .claude/hooks/guard-core.mjs ; echo "exit=$?"

# 2. Fichier core/ sans test → exit 0 + JSON deny sur stdout
echo '{"tool_name":"Edit","tool_input":{"file_path":"src/core/foo.ts"}}' \
  | node .claude/hooks/guard-core.mjs ; echo "exit=$?"

# 3. Fichier de test lui-même → exit 0 (silencieux)
echo '{"tool_name":"Edit","tool_input":{"file_path":"src/core/grid.test.ts"}}' \
  | node .claude/hooks/guard-core.mjs ; echo "exit=$?"

# 4. Hors core/ → exit 0 (silencieux)
echo '{"tool_name":"Edit","tool_input":{"file_path":"src/app/page.tsx"}}' \
  | node .claude/hooks/guard-core.mjs ; echo "exit=$?"
```

### 4. Le check

```bash
npm run check:2.4   # doit être vert
```
